# React یا Angular یا Vue؟ راهنمای انتخاب فریم‌ورک فرانت‌اند برای برنامه‌نویسان JavaScript

فرض کنید با HTML، CSS و JavaScript یک فروشگاه اینترنتی ساخته‌اید. صفحه محصولات به‌درستی نمایش داده می‌شود، دکمه‌ها کار می‌کنند و اطلاعات از API دریافت می‌شوند. اما بعد از اضافه کردن سبد خرید، فیلتر محصولات، پنل کاربری، اعلان‌ها و چندین صفحه دیگر، نگهداری کدها سخت‌تر می‌شود. حالا برای تغییر یک مقدار باید مطمئن شوید که تمام بخش‌های وابسته به آن هم درست به‌روزرسانی می‌شوند.

اینجاست که یک سؤال مهم مطرح می‌شود: **چرا وقتی JavaScript خودش می‌تواند صفحات وب را کنترل کند، باید سراغ فریم‌ورک‌هایی مثل Angular و Vue یا کتابخانه‌ای مثل React برویم؟**

پاسخ فقط سریع‌تر کدنویسی کردن نیست؛ مسئله اصلی، مدیریت پیچیدگی برنامه است.

اگر JavaScript را بلدید و می‌خواهید قدم بعدی را در مسیر توسعه فرانت‌اند بردارید، در این مقاله ابتدا دلیل شکل‌گیری این ابزارها را بررسی می‌کنیم، سپس با مفهوم SPA آشنا می‌شویم و در ادامه Angular، Vue و React را از نظر سینتکس، نحوه کار با DOM، مدیریت تغییرات و کاربردهای واقعی مقایسه می‌کنیم.

در پایان نیز مشخص می‌کنیم هرکدام برای چه مسیری انتخاب مناسب‌تری هستند و چرا یادگیری React می‌تواند شما را به حوزه‌هایی فراتر از توسعه وب برساند.

## ۱. چرا برنامه‌نویسان به سمت فریم‌ورک‌های فرانت‌اند رفتند؟

برای پاسخ به این سؤال، باید از همان فناوری‌هایی شروع کنیم که از قبل می‌شناسیم: HTML، CSS و JavaScript.

### ۱.۱. HTML، CSS و JavaScript به‌تنهایی چه کاری انجام می‌دهند؟

هرکدام از این فناوری‌ها مسئولیت مشخصی دارند:

- **HTML:** ساختار و محتوای صفحه را تعریف می‌کند.
- **CSS:** ظاهر، چیدمان و انیمیشن‌های صفحه را کنترل می‌کند.
- **JavaScript:** رفتار برنامه، پردازش داده‌ها و تعامل با کاربر را مدیریت می‌کند.

برای مثال، می‌توانیم یک شمارنده ساده بسازیم:

```html
<h1 id="count">0</h1>
<button id="increment">افزایش</button>

<script>
  const countElement = document.querySelector('#count');
  const button = document.querySelector('#increment');

  let count = 0;

  button.addEventListener('click', () => {
    count++;
    countElement.textContent = count;
  });
</script>
```

این کد کاملاً معتبر است و نیازی به هیچ فریم‌ورکی ندارد.

با کلیک روی دکمه، مقدار متغیر `count` تغییر می‌کند و JavaScript متن عنصر HTML را به‌روزرسانی می‌کند.

پس مشکل چیست؟

**مشکل این نیست که JavaScript توانایی انجام این کارها را ندارد؛ مشکل این است که با بزرگ شدن برنامه، مدیریت تغییرات و ارتباط میان بخش‌های مختلف پیچیده‌تر می‌شود.**

### ۱.۲. مشکل اصلی، مدیریت دستی DOM است

DOM یا Document Object Model ساختاری درختی از عناصر و محتوای سند HTML است که مرورگر در اختیار JavaScript قرار می‌دهد.

در مثال قبلی، ما مستقیماً عنصر موردنظر را پیدا کردیم و مقدار آن را تغییر دادیم:

```javascript
countElement.textContent = count;
```

در پروژه‌های کوچک، این روش بسیار ساده و مناسب است. اما فرض کنید همین شمارنده بخشی از یک فروشگاه اینترنتی باشد.

تعداد کالاهای سبد خرید ممکن است در نوار بالای سایت، صفحه سبد خرید، پنل سفارش و بخش پرداخت نمایش داده شود. اگر تعداد کالا تغییر کند، تمام بخش‌هایی که به این مقدار وابسته‌اند باید وضعیت درستی داشته باشند.

اگر هر قسمت به‌صورت مستقل و دستی به‌روزرسانی شود، احتمال بروز خطا افزایش پیدا می‌کند.

مشکلات دیگری نیز وجود دارند:

- مدیریت رویدادها در تعداد زیادی از عناصر
- هماهنگ نگه داشتن داده‌ها و رابط کاربری
- ساخت و حذف مکرر عناصر HTML
- تقسیم برنامه به بخش‌های مستقل و قابل استفاده مجدد
- مدیریت وضعیت مشترک میان اجزای مختلف
- نگهداری و توسعه کد توسط چند برنامه‌نویس

البته این مشکلات با JavaScript خام نیز قابل حل هستند؛ می‌توانیم معماری کامپوننت‌محور بسازیم و ابزارهای اختصاصی بنویسیم. اما لازم نیست هر تیم تمام این زیرساخت‌ها را از ابتدا ایجاد کند.

### ۱.۳. برنامه‌نویسان به چه راهکاری نیاز داشتند؟

ایده اصلی این بود که به‌جای مشخص کردن تمام تغییرات DOM به‌صورت دستی، بتوانیم وضعیت مطلوب رابط کاربری را توصیف کنیم و به ابزار موردنظر اجازه دهیم تغییرات لازم را اعمال کند.

برای مثال، به‌جای اینکه بنویسیم:

«عدد داخل این عنصر را پیدا کن و یک واحد افزایش بده»،

بتوانیم بگوییم:

«این بخش باید مقدار فعلی شمارنده را نمایش دهد.»

سپس اگر مقدار شمارنده تغییر کرد، رابط کاربری نیز به‌طور متناسب به‌روزرسانی شود.

این رویکرد را **Declarative UI یا رابط کاربری اعلامی** می‌نامیم.

در مقابل، هنگامی که خودمان مرحله‌به‌مرحله مشخص می‌کنیم چه عملیات‌هایی روی عناصر DOM اجرا شوند، با رویکرد Imperative سروکار داریم.

این تفاوت یکی از مفاهیم بنیادی در درک React، Angular و Vue است.

### ۱.۴. آیا فریم‌ورک‌ها جایگزین HTML، CSS و JavaScript شدند؟

خیر. این تصور اشتباهی است.

این ابزارها بر پایه فناوری‌های وب ساخته شده‌اند و همچنان از HTML، CSS و JavaScript یا TypeScript استفاده می‌کنند. تفاوت در روش سازمان‌دهی کد، تعریف رابط کاربری و مدیریت تغییرات است.

هر سه ابزار نیز بر پایه کامپوننت‌ها کار می‌کنند. کامپوننت را می‌توان یک بخش مستقل از رابط کاربری دانست که مسئول نمایش بخشی از صفحه و گاهی مدیریت رفتارهای مرتبط با آن است.

برای مثال، یک اپلیکیشن می‌تواند از کامپوننت‌های زیر تشکیل شود:

- `Header`
- `Sidebar`
- `ProductCard`
- `ShoppingCart`
- `LoginForm`

در نتیجه، به‌جای مدیریت تمام صفحه به‌عنوان یک توده بزرگ از کد، برنامه را به بخش‌های کوچک‌تر و قابل نگهداری تقسیم می‌کنیم.

یک نکته مهم: React از نظر تعریف رسمی یک **کتابخانه رابط کاربری** است، نه یک فریم‌ورک جامع به معنای Angular. بااین‌حال، در مقایسه‌های رایج توسعه فرانت‌اند، معمولاً این سه ابزار را در کنار یکدیگر بررسی می‌کنند.

## ۲. SPA چیست و چه ارتباطی با فریم‌ورک‌های فرانت‌اند دارد؟

یکی از الگوهایی که در توسعه اپلیکیشن‌های مدرن وب اهمیت زیادی دارد، SPA است.

SPA مخفف Single-Page Application است؛ یعنی برنامه‌ای که معمولاً یک سند اصلی HTML را بارگذاری می‌کند و سپس بخش زیادی از تغییرات صفحه را با کمک JavaScript، بدون بارگذاری مجدد کامل سند، انجام می‌دهد.

### ۲.۱. سایت چندصفحه‌ای چگونه کار می‌کند؟

در روش سنتی چندصفحه‌ای یا MPA، معمولاً هر مسیر یک سند HTML جدید از سرور دریافت می‌کند.

برای مثال:

1. کاربر وارد `/products` می‌شود.
2. مرورگر سند مربوط به محصولات را دریافت می‌کند.
3. کاربر روی یک محصول کلیک می‌کند.
4. مرورگر سند صفحه محصول را درخواست می‌کند.
5. صفحه جدید بارگذاری می‌شود.

این روش همچنان کاربرد فراوانی دارد و برای بسیاری از سایت‌ها انتخاب مناسبی است.

### ۲.۲. SPA چگونه کار می‌کند؟

در یک SPA، برنامه می‌تواند هنگام حرکت میان مسیرهای مختلف، بخش موردنیاز رابط کاربری را تغییر دهد؛ بدون اینکه در هر جابه‌جایی کل سند HTML دوباره بارگذاری شود.

برای مثال، در یک پنل مدیریتی ممکن است کاربر میان بخش‌های محصولات، سفارش‌ها و کاربران حرکت کند، درحالی‌که پوسته اصلی برنامه همچنان باقی می‌ماند.

فرایند معمول چنین است:

1. برنامه اولیه بارگذاری می‌شود.
2. کاربر روی یک لینک کلیک می‌کند.
3. سیستم مسیریابی، مسیر جدید را تشخیص می‌دهد.
4. داده‌های لازم از سرور دریافت می‌شوند.
5. رابط کاربری متناسب با مسیر و داده‌های جدید به‌روزرسانی می‌شود.

مرورگر همچنان URL را مدیریت می‌کند و APIهایی مانند History API امکان به‌روزرسانی مسیر و مدیریت تاریخچه مرورگر را فراهم می‌کنند، بدون اینکه در هر مرحله مجبور به بارگذاری کامل سند باشیم.

### ۲.۳. آیا SPA باعث می‌شود State همیشه حفظ شود؟

خیر. این نکته به‌ویژه برای برنامه‌نویسانی که تازه وارد توسعه کامپوننت‌محور شده‌اند، مهم است.

در SPA ممکن است هنگام جابه‌جایی میان صفحات، بخشی از کامپوننت‌ها حذف و دوباره ایجاد شوند. در این حالت، وضعیت داخلی آن کامپوننت‌ها لزوماً حفظ نمی‌شود.

برای حفظ داده‌ها باید طول عمر کامپوننت‌ها، محل نگهداری State و نیازهای برنامه را به‌درستی طراحی کنیم.

همچنین SPA لزوماً به معنی حذف کامل درخواست‌های شبکه یا دریافت نکردن HTML جدید در هیچ شرایطی نیست؛ این اصطلاح به الگوی کلی برنامه اشاره دارد.

### ۲.۴. نقش فریم‌ورک در ساخت SPA چیست؟

ساخت SPA با JavaScript خام امکان‌پذیر است، اما با افزایش تعداد مسیرها، کامپوننت‌ها و وضعیت‌های مختلف، به زیرساخت بیشتری نیاز داریم.

فریم‌ورک‌ها و کتابخانه‌های رابط کاربری به ما کمک می‌کنند بخش‌هایی مانند این موارد را منظم‌تر مدیریت کنیم:

- تعریف و ترکیب کامپوننت‌ها
- ارتباط میان داده و رابط کاربری
- تشخیص تغییرات و به‌روزرسانی صفحه
- مدیریت رویدادهای کاربر
- اتصال به سیستم مسیریابی
- مدیریت وضعیت مشترک

بااین‌حال، **SPA یک الگوی معماری است، نه نام دیگر React یا Angular**. هر سه فناوری موردبحث می‌توانند در ساخت SPA استفاده شوند و هر سه امکان استفاده در معماری‌های دیگر را نیز دارند.

## ۳. Angular؛ فریم‌ورکی جامع با ساختار مشخص

Angular یک فریم‌ورک فرانت‌اند است که در اکوسیستم Google توسعه می‌یابد. هدف آن ارائه ساختاری نسبتاً یکپارچه برای ساخت اپلیکیشن‌های وب است.

اگر React را ابزاری انعطاف‌پذیر برای ساخت رابط کاربری در نظر بگیریم، Angular بیشتر شبیه مجموعه‌ای از ابزارها و قراردادهای هماهنگ برای ساخت یک اپلیکیشن کامل است.

### ۳.۱. تفاوت کلیدی Angular با Vue و React چیست؟

مهم‌ترین تفاوت Angular در میزان امکانات داخلی و ساختار رسمی آن است.

در Angular امکاناتی مانند Angular Router، سیستم Forms، Dependency Injection و ابزارهای داخلی برای سازمان‌دهی برنامه در دسترس هستند.

در React، انتخاب بسیاری از این ابزارها به توسعه‌دهنده واگذار می‌شود. در Vue نیز ابزارهای رسمی وجود دارند، اما چارچوب و تجربه توسعه آن با Angular متفاوت است.

Angular همچنین به‌شکل گسترده از TypeScript استفاده می‌کند. در نتیجه، کلاس‌ها، Decoratorها، Typeها و ابزارهای نوع‌دهی بخش مهمی از تجربه توسعه آن هستند.

### ۳.۲. Angular چگونه با DOM کار می‌کند؟

Angular برخلاف React و Vue، بر پایه الگوی معمول Virtual DOM ساخته نشده است.

در Angular ساختار رابط کاربری را معمولاً با Template تعریف می‌کنیم. کامپایلر Angular این Templateها را به کد اجرایی بهینه‌شده تبدیل می‌کند. سپس سازوکار تشخیص تغییر و Bindingها مشخص می‌کنند کدام مقادیر DOM باید به‌روزرسانی شوند.

در نسخه‌های جدید Angular، Signals نیز امکان ردیابی دقیق وابستگی‌های داده‌ای را فراهم می‌کنند و در کنار سازوکارهای تشخیص تغییر قرار می‌گیرند.

بنابراین، این تصور که Angular برای تغییر صفحه باید تمام DOM را از ابتدا بسازد، درست نیست. Angular نیز تغییرات را مدیریت می‌کند تا رابط کاربری با داده‌های جاری هماهنگ باقی بماند.

### ۳.۳. سینتکس Angular چگونه است؟

برای درک سینتکس، همان مثال شمارنده را در Angular پیاده‌سازی می‌کنیم.

**فایل کامپوننت TypeScript:**

```typescript
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true,
  template: ` <button (click)="increment()">Count: {{ count() }}</button> `,
})
export class CounterComponent {
  count = signal(0);

  increment() {
    this.count.update((value) => value + 1);
  }
}
```

در این مثال، چند مفهوم مهم وجود دارد:

- `@Component` مشخصات کامپوننت را تعریف می‌کند.
- `signal(0)` یک مقدار واکنش‌پذیر با مقدار اولیه صفر می‌سازد.
- `{{ count() }}` مقدار Signal را در Template نمایش می‌دهد.
- `(click)="increment()"` رویداد کلیک را به متد کامپوننت متصل می‌کند.

Angular برای ارتباط میان Template و داده از Bindingهای مختلف استفاده می‌کند:

```html
<h1>{{ title }}</h1>

<input [value]="name" />

<button (click)="save()">Save</button>
```

در این سینتکس:

- `{{ ... }}` برای نمایش مقدار استفاده می‌شود.
- `[value]` مقدار یک Property را از داده‌های برنامه به عنصر منتقل می‌کند.
- `(click)` رویداد کلیک را به یک عبارت یا متد متصل می‌کند.

از آنجا که Angular Template مبتنی بر HTML است، بخش نمایشی و کلاس TypeScript معمولاً مسئولیت‌های متمایزی دارند.

### ۳.۴. Angular چگونه SPA را مدیریت می‌کند؟

Angular ابزار داخلی Angular Router را برای مدیریت مسیرها فراهم می‌کند.

برای مثال، می‌توان مسیرهایی مانند `/products`، `/users` و `/settings` را تعریف کرد و مشخص کرد هر مسیر چه کامپوننتی را نمایش دهد.

هنگامی که کاربر میان این مسیرها حرکت می‌کند، Router می‌تواند کامپوننت مناسب را در محل مشخص‌شده رندر کند و URL و تاریخچه مرورگر را مدیریت کند.

Angular Router همچنین از امکاناتی مانند مسیرهای تو‌در‌تو، پارامترهای مسیر، Lazy Loading و Route Guards پشتیبانی می‌کند.

این امکانات در برنامه‌های بزرگ اهمیت زیادی دارند؛ چون مسیریابی دیگر فقط به معنای عوض کردن یک کامپوننت نیست و می‌تواند با دسترسی کاربران، بارگذاری داده‌ها و ساختار بخش‌های مختلف برنامه ارتباط داشته باشد.

### ۳.۵. چرا و کجا از Angular استفاده می‌کنیم؟

Angular معمولاً برای پروژه‌هایی مناسب است که به ساختار مشخص، قراردادهای توسعه یکپارچه و مجموعه‌ای از ابزارهای داخلی نیاز دارند.

موارد استفاده رایج آن عبارت‌اند از:

- سامانه‌های سازمانی
- پنل‌های مدیریتی بزرگ
- نرم‌افزارهای مالی و منابع انسانی
- سامانه‌های دارای فرم‌های پیچیده
- پروژه‌هایی با تیم توسعه بزرگ و چندین بخش وابسته

فرض کنید قرار است یک نرم‌افزار ERP با ماژول‌های مالی، انبار، منابع انسانی و گزارش‌گیری توسعه دهید. وجود الگوهای مشترک و ابزارهای رسمی می‌تواند به هماهنگی تیم کمک کند.

البته این موضوع به معنای نامناسب بودن React یا Vue برای ERP نیست؛ هر سه قادر به ساخت چنین محصولی هستند. انتخاب به معماری، تجربه تیم و نیازهای پروژه وابسته است.

### ۳.۶. آیا Angular برای شروع مناسب است؟

اگر JavaScript را بلدید، یادگیری Angular ممکن است در ابتدا به تمرکز بیشتری نیاز داشته باشد؛ زیرا علاوه بر مفاهیم کامپوننت‌محور، باید ساختار خاص Angular، TypeScript، Dependency Injection، Templateها و سیستم واکنش‌پذیری آن را یاد بگیرید.

اما اگر از ابتدا می‌خواهید با یک فریم‌ورک جامع و قراردادهای مشخص کار کنید، Angular انتخاب منطقی‌ای است.

**نکته کلیدی:** Angular برای کسانی جذاب‌تر است که ساختار و یکپارچگی ابزارهای داخلی را به آزادی بیشتر در انتخاب کتابخانه‌ها ترجیح می‌دهند.

## ۴. Vue؛ فریم‌ورکی پیش‌رونده با سینتکس نزدیک به HTML

Vue یک فریم‌ورک پیش‌رونده برای ساخت رابط کاربری است. این فریم‌ورک به شما اجازه می‌دهد با ساختار نسبتاً ساده‌ای شروع کنید و به‌تدریج قابلیت‌های بیشتری به برنامه اضافه کنید.

ویژگی مهم Vue این است که برای استفاده از آن لازم نیست از همان ابتدا تمام پروژه خود را به یک معماری پیچیده تبدیل کنید.

### ۴.۱. تفاوت کلیدی Vue با Angular و React چیست؟

یکی از ویژگی‌های برجسته Vue، استفاده از Templateهایی است که شباهت زیادی به HTML دارند و با یک سیستم واکنش‌پذیری یکپارچه کار می‌کنند.

در Angular نیز Template مبتنی بر HTML داریم، اما Angular مجموعه‌ای گسترده‌تر از قراردادها و ساختارهای داخلی را ارائه می‌دهد.

در React، رابط کاربری معمولاً با JSX و در قالب کد JavaScript تعریف می‌شود.

Vue تلاش می‌کند ساختار HTMLمانند، منطق JavaScript و استایل CSS را در کامپوننت‌هایی قابل سازمان‌دهی ترکیب کند. در بسیاری از پروژه‌های آن، هر کامپوننت در یک فایل `.vue` قرار می‌گیرد.

### ۴.۲. Vue چگونه با DOM کار می‌کند؟

Vue از Virtual DOM استفاده می‌کند، اما نکته مهم نحوه ترکیب آن با سیستم واکنش‌پذیری و کامپایلر Template است.

وقتی یک Template می‌نویسیم، Vue می‌تواند آن را به توابع رندر تبدیل کند. در فرایند ساخت، کامپایلر بخش‌های ثابت و پویا را تحلیل می‌کند و اطلاعاتی برای بهینه‌سازی در اختیار سیستم رندر قرار می‌دهد.

در زمان اجرا، سیستم واکنش‌پذیری وابستگی میان داده‌ها و بخش‌های استفاده‌کننده از آن‌ها را دنبال می‌کند. اگر داده‌ای تغییر کند، بخش‌های وابسته برای به‌روزرسانی مشخص می‌شوند.

سپس Virtual DOM جدید با نسخه قبلی مقایسه می‌شود و تغییرات لازم روی DOM واقعی اعمال می‌شوند.

این رویکرد به Vue امکان می‌دهد از ساختار Templateمحور و بهینه‌سازی‌های زمان کامپایل بهره ببرد.

### ۴.۳. سینتکس Vue چگونه است؟

همان شمارنده را در Vue پیاده‌سازی می‌کنیم:

```vue
<script setup>
import { ref } from 'vue';

const count = ref(0);

function increment() {
  count.value++;
}
</script>

<template>
  <button @click="increment">Count: {{ count }}</button>
</template>
```

در این مثال:

- `ref(0)` یک مقدار واکنش‌پذیر ایجاد می‌کند.
- `count.value` برای خواندن یا تغییر مقدار Ref در JavaScript استفاده می‌شود.
- `{{ count }}` مقدار را در Template نمایش می‌دهد؛ Vue در اینجا Ref را به‌طور خودکار باز می‌کند.
- `@click="increment"` رویداد کلیک را به تابع متصل می‌کند.

در Vue، `@click` شکل کوتاه `v-on:click` است.

Vue همچنین از Directiveهایی برای کنترل نمایش و تکرار عناصر استفاده می‌کند:

```html
<p v-if="isLoggedIn">خوش آمدید</p>

<ul>
  <li v-for="product in products" :key="product.id">{{ product.name }}</li>
</ul>
```

`v-if` نمایش شرطی را مدیریت می‌کند و `v-for` برای تکرار عناصر به کار می‌رود. عبارت `:key` نیز به Vue کمک می‌کند هویت عناصر فهرست را در فرایند به‌روزرسانی تشخیص دهد.

### ۴.۴. Vue چگونه SPA را مدیریت می‌کند؟

Vue به‌تنهایی مانند Angular Router داخلی در هسته اصلی خود ندارد، اما ابزار رسمی و شناخته‌شده آن، Vue Router، برای این کار استفاده می‌شود.

با Vue Router می‌توان مسیرهای مختلف برنامه را تعریف کرد و برای هر مسیر کامپوننت مناسب را نمایش داد.

برای مثال:

- `/products` برای فهرست محصولات
- `/products/12` برای جزئیات یک محصول
- `/profile` برای پروفایل کاربر

Vue Router تغییر مسیر، پارامترها، مسیرهای تو‌در‌تو و سایر امکانات مسیریابی را مدیریت می‌کند.

وقتی مسیر تغییر می‌کند، Vue کامپوننت‌های لازم را رندر می‌کند. این کار معمولاً بدون بارگذاری مجدد کامل سند انجام می‌شود.

مانند Angular و React، حفظ State نیز به ساختار برنامه وابسته است. تغییر مسیر به‌تنهایی تضمین نمی‌کند که تمام وضعیت‌ها در حافظه باقی بمانند.

### ۴.۵. چرا و کجا از Vue استفاده می‌کنیم؟

Vue برای پروژه‌هایی مناسب است که توسعه‌دهندگان به سینتکس قابل‌فهم، انعطاف‌پذیری و ورود تدریجی به توسعه کامپوننت‌محور اهمیت می‌دهند.

موارد استفاده آن شامل این موارد است:

- سایت‌های تعاملی
- داشبوردها و پنل‌های مدیریتی
- فروشگاه‌های اینترنتی
- ابزارهای داخلی سازمان‌ها
- افزودن قابلیت‌های تعاملی به سایت‌های موجود

برای مثال، فرض کنید یک سایت قدیمی با HTML و JavaScript دارید و فقط می‌خواهید بخش فیلتر محصولات را به شکل کامپوننت‌محور بازنویسی کنید. Vue امکان استفاده تدریجی از قابلیت‌های خود را فراهم می‌کند.

### ۴.۶. آیا Vue ساده‌ترین انتخاب است؟

برای بسیاری از برنامه‌نویسانی که با HTML و JavaScript آشنایی دارند، شروع کار با Vue نسبتاً ساده است؛ زیرا Templateهای آن به HTML شباهت دارند.

بااین‌حال، سادگی شروع نباید با سادگی تمام پروژه اشتباه گرفته شود. در برنامه‌های بزرگ، مدیریت State، طراحی معماری، مسیریابی و نگهداری کد همچنان به دانش و تجربه نیاز دارند.

**نکته کلیدی:** Vue انتخاب مناسبی است اگر می‌خواهید با ساختار قابل‌فهم و نسبتاً کم‌اصطکاک شروع کنید، بدون اینکه مجبور باشید از همان ابتدا تمام تصمیم‌های معماری یک فریم‌ورک جامع را بپذیرید.

## ۵. React؛ کتابخانه‌ای برای رابط کاربری، فراتر از مرورگر

تا اینجا Angular را به‌عنوان فریم‌ورکی جامع و Vue را به‌عنوان فریم‌ورکی پیش‌رونده بررسی کردیم. اکنون به React می‌رسیم؛ ابزاری که تفاوت مهم آن فقط در سینتکس یا نحوه رندر DOM نیست، بلکه به معماری و اکوسیستم اطراف آن نیز مربوط می‌شود.

React توسط Meta توسعه یافته و بر ساخت رابط‌های کاربری کامپوننت‌محور تمرکز دارد.

### ۵.۱. تفاوت کلیدی React با Angular و Vue چیست؟

React در هسته خود روی تعریف رابط کاربری و به‌روزرسانی آن با تغییر داده‌ها تمرکز می‌کند. برخلاف Angular، ابزارهای اصلی مانند Router و سیستم فرم جامع در هسته خود React ارائه نمی‌شوند.

این طراحی آزادی بیشتری به توسعه‌دهنده می‌دهد تا ابزارها و معماری مناسب خود را انتخاب کند.

اما نکته مهم‌تر این است که React فقط به رندر کردن رابط کاربری در مرورگر محدود نیست. مدل کامپوننت‌ها، Hooks و شیوه توصیف رابط کاربری آن می‌توانند توسط Rendererهای مختلف به کار گرفته شوند.

در بخش بعدی، این موضوع را با نمونه‌های واقعی بررسی می‌کنیم.

### ۵.۲. React چگونه با DOM کار می‌کند؟

React در وب معمولاً از React DOM برای تبدیل خروجی کامپوننت‌ها به عناصر واقعی مرورگر استفاده می‌کند.

در React، به‌جای اینکه خودمان مستقیماً DOM را با متدهایی مانند `querySelector` و `textContent` به‌روزرسانی کنیم، خروجی موردنظر رابط کاربری را در قالب JSX تعریف می‌کنیم.

وقتی State تغییر می‌کند، React رندر را دوباره انجام می‌دهد، خروجی جدید کامپوننت‌ها را محاسبه می‌کند و در مرحله Reconciliation تفاوت‌های لازم را مشخص می‌کند. سپس تغییرات ضروری را روی DOM واقعی اعمال می‌کند.

درک این نکته مهم است که **رندر شدن دوباره یک کامپوننت الزاماً به معنای تغییر DOM واقعی نیست**. ممکن است خروجی محاسبه‌شده با خروجی قبلی یکسان باشد و در نتیجه نیازی به تغییر DOM نباشد.

این فرایند با Virtual DOM ارتباط دارد، اما نباید تصور کنیم React در هر تغییر، تمام صفحه واقعی را پاک می‌کند و از ابتدا می‌سازد.

### ۵.۳. سینتکس React چگونه است؟

همان مثال شمارنده را با React می‌نویسیم:

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  function increment() {
    setCount((value) => value + 1);
  }

  return <button onClick={increment}>Count: {count}</button>;
}

export default Counter;
```

در این مثال:

- `useState(0)` وضعیت شمارنده را با مقدار اولیه صفر تعریف می‌کند.
- `count` مقدار جاری را در اختیار کامپوننت قرار می‌دهد.
- `setCount` برای درخواست به‌روزرسانی State استفاده می‌شود.
- `onClick={increment}` رویداد کلیک را به تابع متصل می‌کند.
- JSX ساختار رابط کاربری را در کنار JavaScript تعریف می‌کند.

نکته مهم در React این است که مقدار State را مانند یک متغیر معمولی تغییر نمی‌دهیم. برای درخواست به‌روزرسانی، از تابع Setter استفاده می‌کنیم تا React بتواند رندر بعدی را مدیریت کند.

### ۵.۴. تفاوت JSX با Templateهای Angular و Vue چیست؟

این تفاوت را می‌توان یکی از مهم‌ترین نکات سینتکسی این سه فناوری دانست.

در Angular، ساختار HTMLمانند از منطق TypeScript تفکیک می‌شود و با Bindingها به آن متصل می‌شود.

در Vue، Templateها به HTML شباهت زیادی دارند و با Directiveهایی مانند `v-if` و `v-for` قابلیت‌های پویا پیدا می‌کنند.

در React، با JSX ساختار رابط کاربری را در قالب عباراتی نزدیک به JavaScript تعریف می‌کنیم.

برای نمایش شرطی، مثلاً در React می‌توانیم بنویسیم:

```jsx
return <div>{isLoggedIn ? <p>خوش آمدید</p> : <p>لطفاً وارد شوید</p>}</div>;
```

این روش باعث می‌شود شرط‌ها، حلقه‌ها و منطق ترکیب کامپوننت‌ها مستقیماً با امکانات JavaScript قابل بیان باشند.

البته JSX خود JavaScript استاندارد نیست؛ سینتکسی است که در فرایند ساخت به کد قابل اجرا تبدیل می‌شود.

### ۵.۵. React چگونه SPA را مدیریت می‌کند؟

React به‌تنهایی سیستم مسیریابی داخلی ندارد. برای ساخت یک SPA معمولاً از کتابخانه‌ای مانند React Router استفاده می‌کنیم.

React Router امکان تعریف مسیرها، مسیرهای تو‌در‌تو، پارامترها و کنترل جابه‌جایی میان صفحات را فراهم می‌کند.

برای مثال، در یک فروشگاه می‌توانیم مسیرهای `/products`، `/products/12` و `/cart` را تعریف کنیم و در هر مسیر کامپوننت مناسب را نمایش دهیم.

هنگامی که کاربر مسیر را تغییر می‌دهد، Router مشخص می‌کند چه رابط کاربری نمایش داده شود و React DOM تغییرات لازم را روی DOM اعمال می‌کند.

نکته مهم این است که React ذاتاً فقط برای SPA ساخته نشده است. می‌توان از React در بخش کوچکی از یک سایت استفاده کرد، از فریم‌ورک‌هایی مانند Next.js بهره برد یا رابط کاربری را با روش‌های دیگری رندر کرد.

### ۵.۶. چرا و کجا از React استفاده می‌کنیم؟

React برای ساخت رابط‌های کاربری متنوعی استفاده می‌شود؛ از وب‌سایت‌ها و داشبوردها گرفته تا اپلیکیشن‌های پیچیده و محصولات چندسکویی.

موارد استفاده رایج آن عبارت‌اند از:

- فروشگاه‌های اینترنتی
- شبکه‌های اجتماعی
- داشبوردهای SaaS
- پنل‌های مدیریتی
- اپلیکیشن‌های تحت وب با تعاملات زیاد
- رابط‌های کاربری در برنامه‌های موبایل و دسکتاپ

اما مزیت مهم React فراتر از این فهرست است: **مدل کامپوننت‌محور و منطق ساخت رابط کاربری آن در محیط‌های مختلف قابل استفاده است، به شرط آنکه Renderer و ابزارهای مخصوص همان محیط را داشته باشیم.**

### ۵.۷. React Native؛ ساخت اپلیکیشن موبایل

React Native از مفاهیم React مانند کامپوننت‌ها، Props، State و Hooks استفاده می‌کند، اما برای ساخت رابط کاربری موبایل به کامپوننت‌های مخصوص خود متکی است.

برای مثال، در React وب می‌توانیم از عناصر HTML مانند `div` و `button` استفاده کنیم. در React Native، معمولاً از کامپوننت‌هایی مانند `View`، `Text` و `Pressable` استفاده می‌شود.

نمونه‌ای ساده:

```jsx
import { useState } from 'react';
import { View, Text, Pressable } from 'react-native';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <View>
      <Text>Count: {count}</Text>

      <Pressable onPress={() => setCount((c) => c + 1)}>
        <Text>افزایش</Text>
      </Pressable>
    </View>
  );
}
```

همان مفاهیم اصلی React را در محیط موبایل به کار می‌گیریم، اما عناصر رابط کاربری دیگر HTML نیستند. React Native با استفاده از زیرساخت خود، رابط کاربری مناسب پلتفرم موبایل را ایجاد می‌کند.

این موضوع امکان انتقال بسیاری از دانش و الگوهای React از وب به موبایل را فراهم می‌کند، هرچند تمام کدهای UI وب الزاماً قابل استفاده مستقیم در React Native نیستند.

### ۵.۸. Ink؛ استفاده از React در ترمینال

یکی از مثال‌های جالب اکوسیستم React، کتابخانه Ink است.

Ink به توسعه‌دهندگان اجازه می‌دهد برای برنامه‌های خط فرمان یا CLI رابط کاربری تعاملی بسازند؛ یعنی به‌جای استفاده از خروجی متنی ساده، بتوانیم رابطی شامل کامپوننت‌ها، وضعیت و چیدمان داشته باشیم.

برای مثال:

```jsx
import { useState } from 'react';
import { render, Text } from 'ink';

function App() {
  const [count, setCount] = useState(0);

  return <Text>Count: {count}</Text>;
}

render(<App />);
```

این مثال یک رابط ساده ترمینالی را نمایش می‌دهد. در برنامه‌های تعاملی واقعی می‌توانیم رویدادهای صفحه‌کلید، به‌روزرسانی وضعیت و چیدمان اجزای مختلف را نیز مدیریت کنیم.

Ink برای رندر خروجی ترمینال طراحی شده است، نه DOM مرورگر. بنابراین، هرچند از مدل کامپوننت‌محور React استفاده می‌کند، محیط و عناصر رندر آن متفاوت‌اند.

### ۵.۹. OpenTUI؛ رابط‌های ترمینالی با React و TypeScript

OpenTUI نیز نمونه دیگری از این ایده است.

OpenTUI یک هسته رابط کاربری ترمینال با پیاده‌سازی Native و اتصالات TypeScript است و یک بسته React نیز ارائه می‌کند. در این مدل، می‌توان از کامپوننت‌ها، Hooks و State برای ساخت رابط‌های ترمینالی استفاده کرد.

تفاوت مهم این است که OpenTUI فقط یک کتابخانه جاوااسکریپت برای چاپ متن نیست؛ هسته آن مسئول رندر، چیدمان و مدیریت ورودی ترمینال است.

در نتیجه، استفاده از React در این محیط به معنای رندر کامپوننت‌ها در DOM نیست، بلکه به معنای استفاده از مدل توسعه React با Renderer متناسب با ترمینال است.

### ۵.۱۰. Preact؛ نسخه‌ای سبک‌تر با سازگاری نزدیک به React

Preact کتابخانه‌ای برای ساخت رابط‌های کاربری وب است که روی حجم کم و عملکرد متمرکز شده است.

Preact از الگوهای آشنای React مانند کامپوننت‌ها و Hooks پشتیبانی می‌کند و با استفاده از لایه سازگاری خود، می‌تواند با بخش بزرگی از اکوسیستم React تعامل داشته باشد.

این ویژگی به توسعه‌دهندگان اجازه می‌دهد در برخی پروژه‌ها از تجربه و الگوهای آموخته‌شده در React استفاده کنند، درحالی‌که به راهکاری سبک‌تر برای رندر رابط کاربری وب نیاز دارند.

Preact می‌تواند برای ابزارهای کوچک، ویجت‌های تعاملی و رابط‌های وب روی دستگاه‌های محدود از نظر منابع نیز گزینه مناسبی باشد.

البته باید توجه کرد که Preact خود React نیست و همه تفاوت‌های این دو کتابخانه از بین نمی‌روند. همچنین استفاده از Preact در یک رابط وب مربوط به دستگاه IoT را نباید با توسعه Firmware یا اجرای مستقیم React روی سخت‌افزار اشتباه گرفت.

### ۵.۱۱. Electron؛ ساخت برنامه دسکتاپ با JavaScript و React

Electron فریم‌ورکی برای ساخت اپلیکیشن‌های دسکتاپ با فناوری‌های وب مانند HTML، CSS و JavaScript است.

Electron با استفاده از Chromium و Node.js، محیطی برای اجرای برنامه‌های دسکتاپ روی سیستم‌عامل‌هایی مانند Windows، macOS و Linux فراهم می‌کند.

در این محیط می‌توان رابط کاربری را با React ساخت و از مزایای معماری کامپوننت‌محور آن بهره برد.

برای مثال، یک نرم‌افزار مدیریت پروژه یا ابزار توسعه می‌تواند رابط خود را با React پیاده‌سازی کند و از Electron برای قابلیت‌های دسکتاپی و بسته‌بندی برنامه استفاده کند.

البته Electron به React وابسته نیست و می‌توان در آن از فناوری‌های دیگر برای ساخت رابط کاربری استفاده کرد.

### ۵.۱۲. آیا یادگیری React به معنی توانایی توسعه در تمام پلتفرم‌هاست؟

خیر. یادگیری React به‌تنهایی شما را به توسعه‌دهنده مسلط به موبایل، دسکتاپ، ترمینال و سیستم‌های تعبیه‌شده تبدیل نمی‌کند.

مزیت اصلی آن این است که مفاهیم مهمی مانند کامپوننت‌ها، Props، مدیریت State و تفکر اعلامی را یاد می‌گیرید؛ مفاهیمی که می‌توانند در محیط‌های دیگری نیز به کار روند.

برای هر پلتفرم باید APIها، ابزارهای ساخت، مدل رندر، محدودیت‌ها و ملاحظات مخصوص آن را یاد بگیرید.

بنابراین، ارزش اکوسیستم React در **قابلیت انتقال بخش مهمی از دانش و الگوهای توسعه به محیط‌های دیگر** است، نه در یکسان بودن کامل کدها در همه‌جا.

## ۶. مقایسه نهایی Angular، Vue و React

حالا که هر سه فناوری را جداگانه بررسی کردیم، می‌توانیم تفاوت‌های اصلی را در یک جدول ببینیم.

| معیار                       | Angular                                 | Vue                                  | React                               |
| --------------------------- | --------------------------------------- | ------------------------------------ | ----------------------------------- |
| نوع ابزار                   | فریم‌ورک جامع                           | فریم‌ورک پیش‌رونده                   | کتابخانه UI                         |
| ساختار رابط کاربری          | Template                                | Template یا Render Function          | JSX یا APIهای رندر                  |
| کار با DOM                  | Template کامپایل‌شده و Change Detection | Virtual DOM و بهینه‌سازی‌های کامپایل | Virtual DOM و Reconciliation        |
| واکنش‌پذیری                 | Signals و سازوکار تشخیص تغییر           | سیستم Reactivity                     | مدل رندر مبتنی بر State و Hooks     |
| مسیریابی                    | Angular Router                          | معمولاً Vue Router                   | معمولاً React Router یا ابزار مشابه |
| زبان رایج                   | TypeScript                              | JavaScript یا TypeScript             | JavaScript یا TypeScript            |
| یادگیری اولیه               | نسبتاً دشوار                            | نسبتاً آسان                          | متوسط                               |
| میزان آزادی در انتخاب ابزار | کمتر و ساختارمندتر                      | بالا                                 | بسیار بالا                          |
| استفاده فراتر از وب         | به‌طور معمول متمرکز بر وب               | عمدتاً وب                            | اکوسیستم چند Renderer               |
| مناسب برای                  | پروژه‌های جامع و ساختارمند              | توسعه انعطاف‌پذیر با شروع ساده       | وب و اکوسیستم گسترده رابط کاربری    |

این مقایسه یک جمع‌بندی کلی است. مثلاً React می‌تواند با استفاده از فریم‌ورک‌های مکمل به یک راهکار جامع برای توسعه اپلیکیشن تبدیل شود؛ در مقابل، Angular و Vue نیز امکان انتخاب کتابخانه‌های مکمل را دارند.

هیچ‌کدام از این فناوری‌ها همیشه سریع‌تر، ساده‌تر یا مناسب‌تر از بقیه نیستند. نتیجه به نوع پروژه، معماری و توانایی تیم بستگی دارد.

## ۷. اگر JavaScript بلدید، کدام را انتخاب کنید؟

حالا به سؤال اصلی می‌رسیم: اگر با JavaScript آشنا هستید و می‌خواهید یک فریم‌ورک یا کتابخانه رابط کاربری یاد بگیرید، بهتر است از کجا شروع کنید؟

### React را انتخاب کنید اگر...

می‌خواهید در توسعه فرانت‌اند انعطاف‌پذیر باشید، به اکوسیستم بزرگی دسترسی داشته باشید و در آینده مسیرهایی مانند Next.js، React Native یا ساخت ابزارهای تعاملی با React را بررسی کنید.

React همچنین برای کسانی مناسب است که دوست دارند منطق برنامه و ساختار رابط کاربری را با JavaScript و JSX در کنار یکدیگر تعریف کنند.

### Angular را انتخاب کنید اگر...

به پروژه‌های سازمانی علاقه دارید، با TypeScript راحت هستید یا می‌خواهید در محیطی کار کنید که ابزارهای داخلی، ساختار مشخص و قراردادهای معماری اهمیت زیادی دارند.

اگر شرکتی که قصد استخدام در آن را دارید از Angular استفاده می‌کند، یادگیری مستقیم آن می‌تواند منطقی‌تر از یادگیری یک فناوری دیگر باشد.

### Vue را انتخاب کنید اگر...

می‌خواهید مسیر شروع ساده‌تری داشته باشید، سینتکس نزدیک به HTML را ترجیح می‌دهید یا قصد دارید قابلیت‌های تعاملی را به‌تدریج به یک سایت اضافه کنید.

Vue نیز برای ساخت پروژه‌های جدی مناسب است و نباید صرفاً به دلیل سادگی یادگیری، آن را به پروژه‌های کوچک محدود دانست.

### آیا بهتر است هر سه را یاد بگیریم؟

در نهایت، آشنایی با هر سه می‌تواند مزیت باشد؛ اما برای شروع حرفه‌ای، معمولاً بهتر است ابتدا روی یکی متمرکز شوید.

یادگیری هم‌زمان چند ابزار بدون ساخت پروژه واقعی ممکن است باعث شود تفاوت‌های ظاهری سینتکس را حفظ کنید، اما درک عمیقی از State، مدیریت داده، معماری کامپوننت‌ها و چرخه رندر به دست نیاورید.

پیشنهاد عملی این است که یک پروژه مشخص، مثلاً یک فروشگاه ساده، انتخاب کنید و آن را با فناوری موردنظر بسازید. سپس مسیریابی، ارتباط با API، فرم‌ها و مدیریت وضعیت را به آن اضافه کنید.

بعد از اینکه این مفاهیم را واقعاً در یک پروژه تجربه کردید، یادگیری فناوری دوم آسان‌تر و هدفمندتر خواهد بود.

## جمع‌بندی

HTML، CSS و JavaScript همچنان پایه توسعه وب هستند. فریم‌ورک‌ها و کتابخانه‌های فرانت‌اند برای حذف این فناوری‌ها ایجاد نشده‌اند؛ آن‌ها به ما کمک می‌کنند رابط‌های کاربری پیچیده را با ساختاری منظم‌تر توسعه دهیم و تغییرات داده‌ها را بهتر مدیریت کنیم.

Angular با ساختار جامع و ابزارهای داخلی خود برای پروژه‌های ساختارمند جذاب است. Vue ترکیبی از سینتکس قابل‌فهم، سیستم واکنش‌پذیری و انعطاف‌پذیری ارائه می‌دهد. React نیز کتابخانه‌ای متمرکز بر رابط کاربری است که با اکوسیستم گسترده و امکان استفاده از Rendererهای مختلف، از مرورگر فراتر می‌رود.

**اگر JavaScript را بلدید و هنوز مسیر مشخصی ندارید، React می‌تواند نقطه شروع مناسبی باشد؛ به‌ویژه اگر می‌خواهید علاوه بر وب، در آینده توسعه موبایل یا رابط‌های کاربری دسکتاپ و ترمینال را نیز تجربه کنید.**

اما انتخاب درست الزاماً انتخاب محبوب‌ترین ابزار نیست. فریم‌ورکی مناسب شماست که با هدف شغلی، نوع پروژه و شیوه یادگیری‌تان هماهنگ باشد.

## سؤالات متداول

### آیا React فریم‌ورک است یا کتابخانه؟

React از نظر رسمی کتابخانه‌ای برای ساخت رابط کاربری است. بسیاری از قابلیت‌های یک اپلیکیشن کامل، مانند مسیریابی یا رندر سمت سرور، معمولاً با ابزارها و فریم‌ورک‌های مکمل فراهم می‌شوند.

### آیا Angular از Virtual DOM استفاده می‌کند؟

خیر، معماری Angular بر پایه Virtual DOM مانند React و Vue نیست. Angular از Templateهای کامپایل‌شده، Bindingها و سازوکار تشخیص تغییر برای هماهنگ نگه داشتن DOM با وضعیت برنامه استفاده می‌کند.

### آیا React از Angular سریع‌تر است؟

نمی‌توان یک پاسخ مطلق داد. عملکرد به ساختار برنامه، حجم JavaScript، نحوه رندر، مدیریت State و پیاده‌سازی وابسته است. مقایسه منصفانه به اندازه‌گیری روی پروژه‌ای مشابه نیاز دارد.

### برای ساخت SPA بهتر است از React استفاده کنیم یا Angular و Vue؟

هر سه برای ساخت SPA مناسب هستند. تفاوت در ساختار برنامه، ابزار مسیریابی، شیوه مدیریت تغییرات و اکوسیستم هرکدام است.

### آیا با یادگیری React می‌توان اپلیکیشن موبایل ساخت؟

با یادگیری React و سپس React Native، می‌توانید از بسیاری از مفاهیم مشترک برای ساخت اپلیکیشن موبایل استفاده کنید. البته React Native به APIها و کامپوننت‌های مخصوص پلتفرم موبایل نیاز دارد.

### آیا React در ترمینال و دسکتاپ هم کاربرد دارد؟

بله. ابزارهایی مانند Ink و OpenTUI امکان ساخت رابط‌های ترمینالی با React را فراهم می‌کنند. در دسکتاپ نیز می‌توان از React برای ساخت رابط کاربری برنامه‌های مبتنی بر Electron استفاده کرد.

### آیا برای یادگیری فریم‌ورک‌های فرانت‌اند باید JavaScript را کامل بلد باشیم؟

لازم نیست تمام جزئیات JavaScript را پیش از شروع یاد گرفته باشید، اما مفاهیمی مانند توابع، آرایه‌ها، Objectها، ماژول‌ها، Promiseها، توابع ناهمگام، Scope و کار با رویدادها اهمیت زیادی دارند.
